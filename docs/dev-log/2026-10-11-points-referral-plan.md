## 二、积分规则（确定版）

### 2.1 赠送
- 新用户注册成功 → 立即到账 **100.00000000** 积分
- 有效期 **30 个自然日**，记录 `points_expires_at`

### 2.2 每日扣减
- 触发时间：每天 **02:00**（服务器本地时间），由 Admin Server 内置后台任务执行
- 扣减算法：**按剩余积分 ÷ 剩余天数** 线性扣，30 天扣完归零
  ```
  第 1 天：100 ÷ 30 = 3.33333333
  第 2 天：96.66666667 ÷ 29 = 3.33333333
  ...
  第 30 天：扣至 0
  ```
- 选择"线性"而非"固定值"的原因：无论何时开始，积分都会在到期日精确归零，不会剩余尾巴

### 2.3 10% 分成（推广）
- 下线每获得一笔积分，其**直接上级**获得该笔金额的 **10%**
- **逐级递减式分成**：上一级拿到的分成金额，再按 10% 传给再上一级，永久逐级、无级差、无上限
- 小于 `0.00000001` 的分成不发放（避免无意义流水，并自然终止深层链条）
- 示例（三层）：
  ```
  B 注册 → B +100，A +10
  C 通过 B 注册 → C +100，B +10，A +1
  最终：A = 11，B = 110，C = 100
  ```

> ⚠ **语义澄清（重要）**：不是"每一级都拿原始金额的 10%"。
> 若为后者，C 注册时 A 会直接拿到 10 而不是 1。
> 用户原话"**B 就是 10 个，那么 A 就是一个 10%**"表明 A 拿的是 B 那 10 块的 10%，即 **1**，
> 因此实现为 `passed = passed * 0.10` 逐级递减。

### 2.4 精度
- 一律使用 `Decimal`，量化 `ROUND_HALF_UP` 到 **8 位小数**
- **禁止使用 float 参与积分运算**（浮点误差会累积成对不上账）

## 三、上下级关系

### 3.1 绑定
- 每个用户有唯一推广码 `ref_code`（6 位大写字母数字）
- 推广链接形如：`https://<域名>/?ref=ABC123`
- 通过该链接注册 → 上级 = 推广码所属用户，**注册时一次性绑定，不可改**
- 注册页会显示"你的推荐人：xxx"，让用户知情

### 3.2 存储
PostgreSQL 采用**闭包表**（closure table），支持任意深度查询：

```sql
user_refs(ancestor, descendant, depth)
-- A->B->C 会写入：
-- (B,B,0) (A,B,1) (C,C,0) (B,C,1) (A,C,2)
```

- 查全部下级：`WHERE ancestor=我 AND depth>0`
- 查所有上级：`WHERE descendant=我 AND depth>0 ORDER BY depth`

JSON 兜底模式下用父子链 + BFS 实现等价语义。

### 3.3 防环
- 不能绑定自己
- 绑定发生在注册时刻（此时新用户无下级），天然无环
